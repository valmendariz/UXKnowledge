# UX Patterns

This folder contains approval-ready interaction patterns and usage examples that are intended to be reused across product experiences.

## Purpose

Patterns describe practices that are known to work within the repository's governed UX system. They should remain broadly reusable while staying scoped to explicit product and UX expectations.

## Rules

- Patterns should link to the standards they support.
- Patterns should not be treated as a substitute for standards.
- If a pattern becomes outdated or superseded, it should be marked accordingly.
- When product-specific behavior is not yet approved, do not imply it is a standard or pattern.

## Typical content

- recurring interaction structures
- flow-level guidance
- empty, loading, and error handling patterns
- progression and recovery patterns
